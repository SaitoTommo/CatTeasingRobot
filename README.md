# Uno × 猫互动测试台

这是一个本地网页，用来手动扮演 ESP32、布置猫与机器人的位置、注入模拟传感器输入，并观察命令和回报。`SIM_UNO` 是 JavaScript 模型，**不是 Arduino 固件**。需要观察真实固件回报时，请给 Uno 烧录 [`UnoCatController`](../uno-firmware/README.md)，再切换“串口连接”模式。

职责划分：**ESP32-S3** 后续接 OV 摄像头，负责采集与处理画面、识别路线标签和猫、判断前向障碍、决定巡游及互动动作；**Arduino Uno** 负责执行电机与声光动作，读取触碰、编码器和左右超声波，并在本地执行运动安全判断。ESP32 向 Uno 发送 `CAMERA_FRONT` 判定及具体动作指令。当前仓库只有 Uno 固件和代替 ESP32 的网页逻辑，尚无 ESP32 固件或真实摄像头识别。HTTP 视频流入口仅为预览预留，不承担图像识别或避障输入。

网页的猫运动输入在 `cat-input.mjs`，只产生猫的位置和触碰输入；`decision-system.mjs` 不依赖网页、画布、串口或猫动作选项，只根据摄像头观测、触碰、告警与时间输出决策。`app.mjs` 接收数据并执行决策，向 Uno 发送协议命令。开始猫动作与启动巡游决策是两项独立操作；页面提供互动参数调试，但不提供手动指定本次回应方式、攻击次数或云端建议等机器人行为编排入口。后续移植 ESP32 时，应以真实 OV 摄像头识别结果和 Uno 事件替换网页输入，并将 `app.mjs` 中的运动执行部分移植到 ESP32；本仓库尚未生成可烧录的 ESP32 固件。

模拟摄像头对猫和路线标签没有距离上限：目标只要落在当前朝向左右各 38° 的视野内，就会被识别，画布上的视野扇形也延伸到边界。这个设定仅用于网页模拟；真实 OV 摄像头的识别距离需要后续实测。

## 启动

在 PowerShell 中进入本目录，运行：

```powershell
node .\server.mjs
```

然后在 Chrome 或 Edge 打开 `http://localhost:8765`。服务器只监听本机 `127.0.0.1`，不需要下载依赖。用 `Ctrl+C` 停止。

## 使用

- 拖动猫、机器人和障碍物；拖动机器人前方的小圆点设置朝向。
- 拖动 A/B/C/D 四个模拟路线标签。网页模拟的 ESP32 保存固定顺序 `A → B → C → D → A`：起点看不到 A 时先旋转搜索；看到当前标签后对准，发送 `DRIVE` 接近至页面设定距离，随后持续原地旋转搜索下一个标签。发现即停、对准并接近；每次最多扫描 360°，仍未发现就停止巡游并记录失败。模拟场景中，若猫持续挡在通往当前标签的路线上，网页会利用场景坐标寻找左右绕行点，分段绕过后继续靠近同一标签；无安全路径时暂停等待。每段动作仍受 Uno 的摄像头前向输入和左右超声波安全判断约束。此绕行依赖测试台的模拟位置，尚不能用于没有真实环境定位的 LIVE 实车模式。当前标签识别只由网页计算，尚未接入真实 AprilTag 摄像头。
- W/A/S/D 移动猫，方向键移动机器人，Q/E 改变朝向，空格停止运动。按住 Shift 可加快位置移动。
- 决策系统发出互动行为后，网页代替 ESP32 拆解为 Uno 运动命令。“寻找猫”开始后最多旋转一圈，猫进入模拟摄像头画面时立即停止；一圈内找不到也停车结束寻找。完整时序见[寻找猫控制约定](./寻找猫控制约定.md)。
- 只有烧录固件的 Uno 板、没有传感器和电机时，连接串口后点“准备空板模拟”。网页发送 `DEBUG_MODE ON`、`DEBUG_MOTOR_MODE DRY_RUN`、`SET_GEOMETRY`，用 `CAMERA_FRONT` 提供模拟摄像头的前方距离，用 `DEBUG_INJECT SONAR LEFT|RIGHT` 提供左右超声波场景距离，并注入触碰。未填写轮距时，空板使用名义值 120 mm；连接实体驱动后应填写实测轮距。空板模式只抑制输出引脚的实际驱动，并替换未接传感器的输入；运动、安全判断和事件回报与 LIVE 走同一套固件代码。前进由摄像头距离保护，转向由对应侧超声波保护；虚拟编码器也经过停转检查。名义脉冲不能代表真实电机运动或传感器性能。
- “传感器注入”中的摄像头告警与 HTTP 告警是一次性输入按钮，点击一次只向独立决策模块提交一个事件；HTTP 按钮手动模拟一次判断结果，不发起 HTTP 请求。猫动作的默认速度为 35 cm/s、攻击间隔为 3500 ms。点击任意触碰位置会发送一次 250 ms 的按下与松开事件，无须启动猫动作场景；Uno 的事件会进入同一个决策入口，找猫最多一圈。前向距离和编码器脉冲是状态输入，只影响正在执行或后续动作，不会让待命的机器人自行移动。前向距离注入后网页会读取 `GET_DISTANCE` 显示 Uno 接收到的值。
- “顶层决策与取景”三栏分别是“猫主动找机器人”“结束互动”和“机器人主动找猫”。猫触碰后的默认装死／声光回应／慢逃／快逃概率为 20/20/30/30%；另有独立的接触中闪光概率 20%。声光回应在接触中停车、闪 LED 并鸣叫，松开后观察猫；旧版保存的三种回应概率原样保留，新增声光回应初始为 0%，可在页面调整四项使其合计 100%。逃跑后的试探／原地观察／恢复巡游概率为 5/35/60%，只抽取一次。默认第 3 轮抓住触碰发生时，按 40/30/30% 选择直接巡游、安静装死或声光装死；装死期间停车，等待猫离开或最多 15 秒。最后一次触碰后 12 秒无新触碰只直接结束互动，不会在逃跑后装死。机器人主动找猫仅在一次性猫状态告警进入。设置保存在当前浏览器，导出 JSON 记录全部参数；旧版概率设置会迁移。PWM 和位移仍须实物标定。
- “左右转向安全距离”分别发送 `SET_SAFE_DISTANCE LEFT|RIGHT <cm>`。Uno 仍读取对应侧真实超声波并执行同一安全判断，读数无效或过期仍拒绝转向；安全距离只是每侧最小净空阈值，默认 5 cm，可设 5–100 cm，运动中不能修改，上电重启后恢复默认。前方由摄像头的 `CAMERA_FRONT` 输入判定，固定阈值为 15 cm。ESP32 客户端以后可发送相同串口命令；设置不需要开启固件调试。
- “面向猫静止取景”默认 5 秒，适用于声光回应、逃跑后的观察与猫状态告警；逃跑前不会等待取景。“逃跑后等待猫追击”默认 10 秒：逃跑后先重新找猫并对准，再停车等待；等待结束后再次检查朝向。模拟器只验证静止与猫仍在画面内，并记录 `photo_taken=false`；真实图像清晰度检测、照片采集和后台分析尚未接入。
- 模拟猫与机器人持续重叠时只算一次触碰；接触区方位变化不会重计。猫离开接触区并产生松开事件后，下一次进入才增加触碰计数。猫攻击场景在实际分开之前不会仅凭攻击计时器重新计数；手动触碰按钮仍是用户主动发起的单次脉冲。
- “指令与事件”区分 `TX·SIM`、`SIM_UNO`、`ESP32·SIM`、`TX·SERIAL` 和 `SERIAL`。导出的 JSON 保存完整会话轨迹。
- “ESP32-S3 摄像头视频流”可填写后续设备提供的 HTTP(S) 视频流 URL 并在页面预览。摄像头模块具体 OV 型号和 HTTP 路径尚未确认，因此页面不预设地址。视频预览与避障数值分开；真实图像识别尚未接入时，视频能显示也不会自动产生 `CAMERA_FRONT`，LIVE 前进仍受无效读数保护。
- 本地模拟中，机器人会随运动命令改变场景位置。串口模式下，网页在运动期间显示名义位置，并在固件回报 `DRIVE` 或 `ROTATE` 完成或中止后按该次编码器脉冲校正画面位置；空板脉冲是虚拟的，LIVE 脉冲来自实际编码器。短时 `MOTOR` 和 `TURN` 的画面转动仍是名义推算，因为低分辨率编码器可能在短脉冲内没有计数。画布位置仍依赖模拟初始姿态和几何参数，不是独立的位置传感器读数。

## 数据驱动演示

1. 拖动机器人、猫和障碍物，设置起点与朝向。
2. 如果只接了已烧录固件的 Uno 板，先连接串口并点“准备空板模拟”，等 `GET_STATUS` 回报中出现 `DEBUG=ON MOTOR_MODE=DRY_RUN`，且 `GET_DISTANCE` 显示前方与左右读数。网页随后按需提供模拟摄像头、左右超声波与触碰输入：静止时不周期发送，转向时不发送前方读数；前进时约每 350 ms 更新一次前方读数，以满足 Uno 的 500 ms 有效期。左右超声波仅在数值明显变化或跨过当前对应侧安全距离阈值时更新。
3. 在“猫的动作输入”中选猫的行为：静止、靠近、跟随、反复攻击或远离。攻击还可选触碰位置、速度、持续时间和间隔。点“开始猫动作”；需要猫离开时选择“远离机器人”。
4. 单独点“启动巡游决策”启动固定标签路线。猫靠近时机器人继续巡游；点击一次性猫状态告警按钮或收到 Uno 触碰时才中断。**只有收到 Uno 回报的 `EVENT ... TOUCH ... PRESS`**，决策系统才把它计为一次攻击。首次触碰独立抽取接触中闪光，并抽取当场装死、接触中声光回应、松开后慢逃或松开后快逃。声光回应同时启动 LED 和蜂鸣器，不转动轮子；松开后观察猫。逃跑按模拟猫位置选择远离猫且有净空的方向，不先找猫或静止取景；逃跑完成后主动搜索并对准猫，等待追击结束再检查朝向。逃跑完成后再从猫主动后续概率中选一次试探、原地观察或恢复巡游。达到轮数的**那次抓住触碰**改由独立三种结局概率决定；无触碰超时只直接结束互动。网页等待 Uno 确认 `SESSION_STOPPED`，再发送 `SESSION_START` 并从被中断的标签目标继续巡游。
5. “顶层决策与取景”面板显示当前输入、选定动作、依据和收尾朝向。日志分别记录 `SIM_CAT`、`DEBUG_INJECT`、Uno 的 `EVENT`、`UNO_TO_ESP32`、`TOP_LEVEL_DECISION`、`FACE_CAT_RESULT` 和底层 TX 命令，可导出 JSON 检查决策依据。

串口模式的巡游找标签和触碰后找猫都通过续发 `MOTOR` 命令旋转，摄像头发现目标后立即 `STOP`；对应侧超声波阻挡时等待空间腾出，再继续同一次搜索，超时仍不安全则结束寻找。找猫期间再次触碰会记录输入，但不会重启已经进行的回应。逃跑会按模拟猫位置计算转角，固件须先收到 `SET_GEOMETRY`；选择方向的净空预测依赖网页模拟场景坐标，LIVE 实车还没有真实环境定位，必须依赖 Uno 对实际摄像头前方输入和左右超声波的拒绝保护，不能把模拟净空当成实测结果。空板准备按钮会设置页面轮径与轮距，轮距留空时填入名义值 120 mm。实际接上驱动后请实测并重新设置几何参数。LIVE 模式的左右避障来自真实超声波，前方需要真实 ESP32 摄像头通过 `CAMERA_FRONT` 提供读数；本网页**不会**把模拟画面的摄像头数据送入 LIVE。真实摄像头尚未接入时，固件拒绝前进。DRY_RUN 使用模拟输入；两种模式共用 Uno 的运动和安全判断。Uno 重启时决策运行停止，需重新确认连接与几何参数。

## ESP32 层的互动动作

### 顶层状态与 Uno 会话命令

| 当前状态 | 触发条件 | 下一状态 | 必须完成的动作或依赖 |
| --- | --- | --- | --- |
| 待命 `IDLE` | 点击“启动巡游决策” | 巡游 `PATROL` | 向 Uno 发送 `SESSION_START` 并等 `SESSION_STARTED`，然后寻找路线标签 |
| 巡游 `PATROL` | Uno 报告触碰按下，或收到一次性猫状态告警 | 互动 `INTERACTION` | 保存当前巡游标签；触碰与告警进入彼此独立的决策分支 |
| 互动 `INTERACTION` | Uno 首次回报触碰按下 | 互动 `INTERACTION` | 立即选定声光或逃跑回应；逃跑须等触碰开关松开，且遵守 Uno 运动安全检查。连击合并窗口只用于把随后快速触碰算作同一轮，不延迟首次回应；每次按下仍记为证据。回应进行中的新触碰不排第二次回应，可提前结束追击等待 |
| 互动 `INTERACTION` | 触碰回应启动失败，包括找不到猫、无法对准或安全中止 | 收尾 `ENDING` | 立即停车，强制选择“直接巡游”，不抽取倒下结局，不等待下一轮决策 |
| 互动 `INTERACTION` | 新一轮抓住触碰达到轮数 | 收尾 `ENDING` | 在触碰当下抽取直接巡游、安静装死或声光装死；装死期间停车，不能先逃跑再装死 |
| 互动 `INTERACTION` | 无新触碰超时或会话上限 | 收尾 `ENDING` | 直接结束互动，不抽取装死结局 |
| 收尾 `ENDING` | 倒下反馈完成或选中直接巡游，且 Uno 确认 `SESSION_STOPPED` | 巡游 `PATROL` 或待命 `IDLE` | 原本在自动巡游则先发送 `SESSION_START` 重新开放 Uno 运动，再继续原目标标签；单独触碰则回待命 |
| 任意运行状态 | 人工停止 | 待命 `IDLE` | 立即发送 `STOP` 停车并取消当前自动决策 |

`INTERACTION`/`ENDING` 是网页模拟 ESP32 的顶层状态；`SESSION_START`/`SESSION_STOP` 是发给 Uno 的底层命令。`SESSION_STOP` 会锁住后续运动，不能用它表示“允许继续巡游”；恢复运动必须再发送 `SESSION_START`。协议没有 `SESSION_END` 命令。

下面是独立决策系统可能输出的行为，以及网页代替 ESP32 执行这些行为时发送的命令。**行为名称本身不会发给 Uno**；日志会显示拆解后的 `DRIVE`、`ROTATE`、`STOP` 等底层命令。速度、距离和停顿时长是初始参数，需要之后用实体电机标定。

| 网页动作 | 输入与拆解方式 | 动作后的处理 |
| --- | --- | --- |
| 固定路线巡游 `PATROL` | ESP32 模拟层按 A/B/C/D 标签顺序读取模拟标签画面；模拟位置显示猫挡路时规划侧边绕行点，分段 `DRIVE` 后回到原标签目标；若机器人刚好处在猫的规划安全边界内，允许沿远离猫的路线退出；抵达指定距离后扫描下一个标签 | 告警或 Uno 触碰时中断巡游；无安全绕行路径则暂停；巡游本身不找猫、不计互动时长 |
| 触碰回应 `ATTACK_RESPONSE` | 首次触碰立即独立抽取接触中闪光，并抽取装死／声光回应／慢逃／快逃。抽中声光回应时，接触中同时发送 `LED FLASH` 与 `BEEP`，不启动轮子；抽中装死则立即停车倒下；逃跑在松开后直接规划远离猫且有净空的路线 | 声光回应松开后观察猫；逃跑后停车并主动搜索、对准猫，等待追击后再次寻找并面向猫静止观察。找猫失败会显式记录；安全中止时停车并退出互动 |
| 缓慢接近 `SLOW_APPROACH` | 模拟摄像头先找猫并对准；按调试距离和 PWM 前进，默认 9 cm、PWM 95 | 停下，重新找猫并对准 |
| 走停试探 `PROBE_APPROACH` | 猫主动触碰后的独立后续概率，或机器人主动找猫时的远处概率选中且各自冷却结束；对准猫后以调试 PWM 分三段前进，默认 3、4、3 cm | 猫离开视野时结束试探；收尾重新找猫并对准 |
| 快速前进 `FAST_FORWARD` | 较高 PWM 直行约 23 cm | 停下，重新找猫并对准 |
| 缓慢直线逃跑 `SLOW_STRAIGHT_ESCAPE` | 等触碰松开，利用模拟猫位置选远离猫且有净空的方向，按调试速度和距离直行，默认 PWM 95、最多 26 cm。需先配置轮径和轮距 | 停下后搜索并对准猫；无安全方向不前进；逃跑动作被猫抓停时，等触碰松开后自动续跑一次，链路错误（如 `UNKNOWN_OR_INVALID_COMMAND`）最多重发 2 次 |
| 快速直线逃跑 `FAST_STRAIGHT_ESCAPE` | 同样不等取景，选远离猫且有净空的方向，默认 PWM 210、最多 26 cm | 停下后搜索并对准猫；抓停续跑与链路重发同慢速逃跑 |
| 被抓摇晃 `CAPTURE_WIGGLE` | 仅供手动演示，原地以较低 PWM 和短时间的 `TURN LEFT/RIGHT` 交替摇晃 | 停止后寻找并对准猫 |
| 机器人主动声光回应 `STAY_SIGNAL` | 机器人主动找到猫并对准后停车、闪灯 1.4 秒、蜂鸣 180 ms | 声光结束后再次检查朝向 |
| 结束互动 `END_SESSION` | 每次被抓住可按触碰回应概率当场装死；达到轮数的那次抓住触碰仍使用独立的三种结局概率。装死时立即停车，可安静或声光示意，等待猫实际离开或最长静止时间。无触碰超时与会话上限只直接结束 | 装死期间不再转向猫；其他收尾可面向猫静止观察。随后发送 `SESSION_STOP` 并等待确认，必要时重试或查询状态；确认后发送 `SESSION_START`，从中断的标签续巡 |

`SEARCH_CAT_START`、`SEARCH_CAT_STOP`、后续的对准猫动作，以及 `OBSERVE` 都属于网页模拟的 ESP32 执行流程；Uno 收到的是具体电机和停止命令。`SEARCH_CAT_STOP` 在“猫进入画面”时触发，对准猫是下一步。逃跑后寻找猫的上限为 360°，默认收尾超时 8 秒。若触碰默认 4 秒未松开或被 Uno 安全保护中止，网页停车并记录失败；若逃跑后找猫失败，会记录 `FACE_CAT_RESULT status=FAILED`，无法保证物理朝向。`SESSION_STOP` 停车并锁住 Uno 的后续运动；`SESSION_START` 才重新开放运动。两者均是底层协议命令。真实系统应由 ESP32 使用摄像头观测和触碰历史确定方向；网页目前使用模拟猫位置规划逃跑、模拟摄像头观测猫，尚无 ESP32 摄像头固件。网页没有验证实体电机在低 PWM 下能否启动，也没有测量真实位移。

## 串口协议

网页发送一行 `CMD <id> <command>`，固件按行返回 `ACK <id>`、`DONE <id>`、`ERROR <id> <reason>`、`EVENT ...`、`DATA ...`。例如：

```text
CMD 12 DRIVE 20 120
ACK 12
EVENT MOTION_STARTED 12 DRIVE ESTIMATED
EVENT MOTION_DONE 12 ESTIMATED LEFT_PULSES=20 RIGHT_PULSES=20
```

示例支持的命令：`PING`、`SESSION_START`、`SESSION_STOP`、`STOP`、`MOVE FORWARD|BACKWARD <pwm> <ms>`、`TURN LEFT|RIGHT <pwm> <ms>`、`DRIVE <cm> <pwm>`、`ROTATE <degrees> <pwm>`、`MOTOR <left_pwm> <right_pwm>`、`LED ON|OFF|FLASH`、`BEEP <ms>`、`GET_STATUS`、`GET_DISTANCE`、`GET_ENCODER`、`GET_CONFIG`、`CAMERA_FRONT <CLEAR|BLOCKED|INVALID|cm>`、`SET_SAFE_DISTANCE LEFT|RIGHT <cm>`。正角度表示向右转。`MOTOR` 500 ms 内未续发会自动停止。模拟距离或角度结果标为 `ESTIMATED`。

串口连接模式下所有命令经统一写队列串行发出，相邻两行至少间隔 15 ms，避免突发压垮 Uno 的 64 字节接收缓冲；运动命令前的传感器同步（`CAMERA_FRONT`、`DEBUG_INJECT SONAR`）逐条等到 `DONE` 才发运动命令。配合 V5.1 固件的收发互不阻塞加固，可消除“逃跑指令被丢字节打碎成 `UNKNOWN_OR_INVALID_COMMAND`”的故障。运动命令遇到此类链路错误自动重发（日志 `MOTION_RETRY`），`SESSION_STOP` 无回执自动重试（日志 `SESSION_STOP_RETRY`）。

调试输入示例：

```text
CMD 13 DEBUG_INJECT TOUCH LEFT PRESS
CMD 14 DEBUG_INJECT TOUCH LEFT RELEASE
CMD 15 CAMERA_FRONT 12
CMD 16 CAMERA_FRONT CLEAR
CMD 17 CAMERA_FRONT INVALID
CMD 18 DEBUG_INJECT ENCODER 10 10
CMD 19 DEBUG_INJECT SONAR LEFT 45
CMD 20 DEBUG_INJECT SONAR RIGHT 50
```

这些是固件已实现的命令。完整参数、安全规则、引脚以及调试模式见 [Uno 固件说明](../uno-firmware/README.md)。串口模式下，发送注入命令前先点“开启固件调试”；如果尚未接电机，再点“电机空转模式”。几何参数区需要填写实测轮距，固件才接受 `ROTATE`。本地 `SIM_UNO` 依旧只模拟协议，不执行固件代码。

## 串口连接

点击“连接 Uno 串口”，选择设备。网页使用 Web Serial、波特率 115200；请用支持 Web Serial 的 Chrome 或 Edge 通过 `localhost` 打开页面。连接后可以手动注入传感器事件；持续场景注入仅在空板模式启用。LIVE 模式的前向摄像头数据源须由真实 ESP32 实现，本仓库目前只定义 Uno 接收协议和 HTTP 视频预览入口，没有实物摄像头算法或 ESP32 串口程序。ESP32-S3 后续可同时提供视频流给网页，并把图像识别得到的前向安全判定以 `CAMERA_FRONT CLEAR|BLOCKED|INVALID`（或经标定的厘米读数）送入 Uno；视频流本身不构成安全读数。

Uno R3 的 D0/D1 硬件串口与 USB 调试共享；Uno 的 5V TX 接 ESP32-S3 RX 需要电平转换。固件引脚分配和接线注意事项见 [Uno 固件说明](../uno-firmware/README.md)。
