左/右电机显示接收的带符号 PWM、实际引脚驱动记录、方向引脚电平及输出开关；编码器显示累计脉冲、约 500 ms 窗口的 RPM、采样瞬间 HIGH/LOW 和物理/虚拟来源。超声波分别显示物理测距和最终控制读数，触碰显示原始电平及去抖状态，LED/蜂鸣器显示逻辑指令与引脚状态。前向判定标注电脑模拟或上位机来源。超过 2.5 秒未更新的单项读数标为过期；断开或 Uno 重启时清空旧值。数字电平不是波形，电机引脚驱动也不是实测电压、电流或转动反馈；真实转动需要看编码器。ENA/ENB 跳线固定使能时，显示 PWM 不代表实际调速；开启通道也不意味着检测到模块已接入。

使用本次页面前，需重启本地测试台服务器以加载新模块路由，刷新网页，并重新烧录主固件 UnoCatController.ino（READY UNO_CAT_V5.6）；独立的 SimpleMotorTest.ino 只接受 A/B/C/D/S，不能提供网页实时协议。界面操作及硬件验证由用户完成。

V5.6 将物理 IO 拆为 14 个独立通道。原空板准备按钮改为“关闭所有物理输出”，只关闭输出且保留输入选择；另有“准备元器件测试（模拟未接输入）”初始化按钮。完整接线和单轮测试步骤见 [元器件接线与电脑测试](./元器件接线与电脑测试.md)。

这是一个本地网页，用来布置猫与机器人的位置、通过碰撞和视野计算模拟传感器输入，并观察命令和回报。`SIM_UNO` 是 JavaScript 模型，**不是 Arduino 固件**。需要观察真实固件回报时，请给 Uno 烧录 [`UnoCatController`](./firmware/README.md)，再切换“串口连接”模式。

职责划分：**ESP32-S3** 后续接 OV 摄像头，负责采集与处理画面、识别路线标签和猫、判断前向障碍、决定巡游及互动动作；**Arduino Uno** 负责执行电机与声光动作，读取触碰、编码器和左右超声波，并在本地执行运动安全判断。ESP32 向 Uno 发送 `CAMERA_FRONT` 判定及具体动作指令。新增 ESP32 固件与实机网页入口见 [ESP32 上位机](./esp32-host/README.md)，独立页面 `/esp32-lab.html` 让 JavaScript 模拟 Uno、ESP32 运行决策，并提供 HTTP 视频及板载猫/AprilTag 识别。实机验证范围见 [验证记录](./esp32-host/VALIDATION.md)。本页仍是原 Uno 测试台。

网页的猫运动输入在 `cat-input.mjs`，只改变猫的场景位置，触碰由车体接触检测产生；`decision-system.mjs` 不依赖网页、画布、串口或猫动作选项，根据 HTTP 触发命令、摄像头观测、触碰与时间输出决策。`app.mjs` 接收数据并执行决策，向 Uno 发送协议命令。开始猫动作与启动巡游决策是两项独立操作；页面提供互动参数调试，但不提供手动指定本次回应方式或攻击次数的行为编排入口；模拟 HTTP 按钮只发送一次性主动互动触发命令。ESP32 的 C++ 决策移植已放入 `esp32-host`，仍需实机行为验收；本页的原网页策略保持独立。

模拟摄像头测量范围为 400 cm、左右各 38°；目标必须通过当前视野与遮挡检测。未检出目标时只返回未检出，不传递目标方位或距离。

## 观测数据边界（2026-09-28）

环境和机器人控制之间只传感测结果。场景坐标仅用于绘图、拖动/猫动作、运动物理更新以及传感器碰撞计算，不能进入规划器。

| 测量 | 生成方式 | 控制侧获得的数据 |
| --- | --- | --- |
| 前向距离 | 当前车头的射线束与墙、障碍物、猫的最近交点 | 当前净空 cm；15 cm 安全阈值 |
| 左右超声波 | 当前左右传感器方向 ±8° 射线束碰撞 | 各侧净空 cm；各自默认 5 cm 阈值 |
| 猫/路线标签视觉 | 当前 ±38° 视野、400 cm 范围和遮挡射线检测 | 检出时的图像横坐标、相对方位和距离；未检出时不输出方位/距离 |
| 触碰 | 车体与猫几何接触、区域划分、去抖 | 开关按下/松开；连续重叠只计一次 |
| 编码器 | 模拟轮子运动或 Uno 回报 | 左右轮计数；配合已生效轮径/轮距累计扫描角度 |

- 已移除全场景坐标绕行点、虚拟旋转后的净空预读、视野外猫距离、根据网页真实朝向累计扫描等路径。
- 巡游只按 A/B/C/D 的任务顺序寻找当前可见标签。绕障采用实际转动后再测量的局部策略，不承诺找到全局路径；无测得通路时停车。
- 逃跑先按可见猫方位或最近触碰方向转向，再读取新的前向距离；最多做有限次数的真实转向尝试。没有预先知道最佳方向的能力。
- “未检测到猫”不等于“猫已经离开”；离开计时需要实际检测到距离超过阈值，否则由明确的互动时限结束。
- 保留一次性模拟 HTTP 指令作为主动互动的触发入口；已移除手填编码器、传感器数值覆盖入口。接触按钮实际临时移动猫；距离框实际放置障碍物，最终读数仍取碰撞结果。
- 参数表改变策略；轮径、轮距、安全距离以执行器确认后的配置为准。原始命令面板不能覆盖传感器值；人工电机命令仍属于操作者指令。
- 空板固件 V5.2 不再把未收到的侧面数据当成 400 cm。侧面测量超过 500 ms 失效；网页运动期间每 1000 ms 刷新侧面、每 350 ms 刷新前向数据。
- `server.mjs` 提供静态资源和一个一次性找猫指令队列：`POST /mood_alert`（请求体 `{"source":"HTTP_NEGATIVE"}`，也接受表单编码）入队，网页每 600ms `GET /mood_alert/pending` 取走一条并交给同一注入入口，模拟上位机 ESP32 真实收到 HTTP 指令。队列只携带意图，从不携带猫的位置；决策仍在浏览器中的独立模块运行，`server.mjs` 不做任何决策。以 `file://` 打开页面时网络通道自动停用，仅剩按钮模拟。

完整检查记录见 [观测边界审计](./OBSERVATION_AUDIT.md)。

## 启动

在 PowerShell 中进入本目录，运行：

```powershell
node .\server.mjs
```

然后在 Chrome 或 Edge 打开 `http://localhost:8765`。服务器只监听本机 `127.0.0.1`，不需要下载依赖。用 `Ctrl+C` 停止。

## 使用

- 拖动猫、机器人和障碍物；拖动机器人前方的小圆点设置朝向。
- 拖动 A/B/C/D 四个模拟路线标签。网页模拟的 ESP32 保存固定顺序 `A → B → C → D → A`：起点看不到 A 时先旋转搜索；看到当前标签后对准，发送 `DRIVE` 接近至页面设定距离，随后持续原地旋转搜索下一个标签。发现即停、对准并接近；每次最多扫描 360°，仍未发现就停止巡游并记录失败。模拟场景中，若猫持续挡在通往当前标签的路线上，网页会利用场景坐标寻找左右绕行点，分段绕过后继续靠近同一标签；无安全路径时暂停等待。每段动作仍受 Uno 的摄像头前向输入和左右超声波安全判断约束。此绕行依赖测试台的模拟位置，尚不能用于没有真实环境定位的 LIVE 实车模式。当前标签识别只由网页计算，尚未接入真实 AprilTag 摄像头。
- W/A/S/D 移动猫，方向键移动机器人，Q/E 改变朝向，空格停止运动。按住 Shift 可加快位置移动。
- 决策系统发出互动行为后，网页代替 ESP32 拆解为 Uno 运动命令。“寻找猫”开始后最多旋转一圈，猫进入模拟摄像头画面时立即停止；一圈内找不到也停车结束寻找。完整时序见[寻找猫控制约定](./寻找猫控制约定.md)。
- 只有烧录固件的 Uno 板、没有传感器和电机时，连接串口后点“准备元器件测试（模拟未接输入）”。网页发送 `DEBUG_MODE ON`、`DEBUG_MOTOR_MODE DRY_RUN`、`SET_GEOMETRY`，用 `CAMERA_FRONT` 提供模拟摄像头的前方距离，用 `DEBUG_INJECT SONAR LEFT|RIGHT` 提供左右超声波场景距离，并注入触碰。未填写轮距时，空板使用名义值 120 mm；连接实体驱动后应填写实测轮距。空板模式只抑制输出引脚的实际驱动，并替换未接传感器的输入；运动、安全判断和事件回报与 LIVE 走同一套固件代码。前进由摄像头距离保护，转向由对应侧超声波保护；虚拟编码器也经过停转检查。名义脉冲不能代表真实电机运动或传感器性能。
- “顶层决策与取景”三栏分别是“猫主动找机器人”“结束互动”和“机器人主动找猫”。猫首次触碰时默认按 20/80% 选择**声光探索／捕猎**分支，一轮连续互动内只选择一次。声光探索每次触碰同时发出 LED 与蜂鸣反馈，常亮、快闪、慢闪和极慢闪四种节奏轮换，一轮四种都用过才重复，连续两次不相同；当前 Uno 只有单路灯输出，暂不支持 RGB 颜色变化。捕猎分支按 20/40/40% 抽取装死／慢逃／快逃。两分支共用回应后的观察、试探或恢复巡游和结束条件。默认第 3 轮抓住触碰发生时，按 40/30/30% 选择直接巡游、安静装死或声光装死；装死期间停车，等待猫离开或最多 15 秒。最后一次触碰后 12 秒无新触碰只直接结束互动。机器人主动互动仅由一次性 HTTP 指令触发；看见猫不会中断巡游。设置保存在当前浏览器，导出 JSON 记录全部参数；上一版混在捕猎概率里的声光份额迁移到慢逃／快逃，保持装死概率。PWM 和位移仍须实物标定。
- 捕猎分支另有独立的“触摸时声光反馈”概率，默认 20%；抽中时在触碰按住期间同时发送 `LED FLASH` 和 `BEEP`，不等待逃跑或改变装死／慢逃／快逃的抽签。声光探索分支每次触摸本身就会发出声光，不叠加这一组反馈。沿用旧设置中的 `touchFlashPercent` 数值，但现在控制灯和蜂鸣器两者。
- “左右转向安全距离”分别发送 `SET_SAFE_DISTANCE LEFT|RIGHT <cm>`。Uno 仍读取对应侧真实超声波并执行同一安全判断，读数无效或过期仍拒绝转向；安全距离只是每侧最小净空阈值，默认 5 cm，可设 5–100 cm，运动中不能修改，上电重启后恢复默认。前方由摄像头的 `CAMERA_FRONT` 输入判定，固定阈值为 15 cm。ESP32 客户端以后可发送相同串口命令；设置不需要开启固件调试。
- “面向猫静止取景”默认 5 秒，适用于声光回应、逃跑后的观察与摄像头检测；逃跑前不会等待取景。“逃跑后等待猫追击”默认 10 秒：逃跑后先重新找猫并对准，再停车等待；等待结束后再次检查朝向。模拟器只验证静止与猫仍在画面内，并记录 `photo_taken=false`；真实图像清晰度检测、照片采集和后台分析尚未接入。
- 模拟猫与机器人持续重叠时只算一次触碰；接触区方位变化不会重计。猫离开接触区并产生松开事件后，下一次进入才增加触碰计数。猫攻击场景在实际分开之前不会仅凭攻击计时器重新计数；接触按钮通过临时移动猫产生真实几何接触。
- “指令与事件”区分 `TX·SIM`、`SIM_UNO`、`ESP32·SIM`、`TX·SERIAL` 和 `SERIAL`。导出的 JSON 保存完整会话轨迹。
- “ESP32-S3 摄像头视频流”可填写后续设备提供的 HTTP(S) 视频流 URL 并在页面预览。摄像头模块具体 OV 型号和 HTTP 路径尚未确认，因此页面不预设地址。视频预览与避障数值分开；真实图像识别尚未接入时，视频能显示也不会自动产生 `CAMERA_FRONT`，LIVE 前进仍受无效读数保护。
- 本地模拟中，机器人会随运动命令改变场景位置。串口模式下，网页在运动期间显示名义位置，并在固件回报 `DRIVE` 或 `ROTATE` 完成或中止后按该次编码器脉冲校正画面位置；空板脉冲是虚拟的，LIVE 脉冲来自实际编码器。短时 `MOTOR` 和 `TURN` 的画面转动仍是名义推算，因为低分辨率编码器可能在短脉冲内没有计数。画布位置仍依赖模拟初始姿态和几何参数，不是独立的位置传感器读数。

## 数据驱动演示

1. 拖动机器人、猫和障碍物，设置起点与朝向。
2. 如果只接了已烧录固件的 Uno 板，先连接串口并点“准备元器件测试（模拟未接输入）”，等 `GET_STATUS` 回报中出现 `DEBUG=ON INPUT_MODE=TEST MOTOR_MODE=OFF`，且 `GET_DISTANCE` 显示前方与左右读数。网页随后按需提供模拟摄像头、左右超声波与触碰输入：静止时不周期发送，转向时不发送前方读数；前进时约每 350 ms 更新一次前方读数，以满足 Uno 的 500 ms 有效期。运动中左右超声波每 1000 ms 更新，跨过安全阈值立即更新，运动前强制更新。
3. 在“猫的动作输入”中选猫的行为：静止、靠近、跟随、反复攻击或远离。攻击还可选触碰位置、速度、持续时间和间隔。点“开始猫动作”；需要猫离开时选择“远离机器人”。
4. 单独点“启动巡游决策”启动固定标签路线。收到一次性 HTTP 指令或 Uno 触碰时中断巡游。**只有收到 Uno 回报的 `EVENT ... TOUCH ... PRESS`**，决策系统才把它计为一次攻击。首次触碰先按概率选声光探索或捕猎，本轮后续触碰沿用同一分支。声光探索在接触中停车并同时启动 LED 和蜂鸣器，每次换一种节奏；松开后观察猫。捕猎抽取当场装死、松开后慢逃或松开后快逃。逃跑按当前视觉方位或最近触碰方向选择初始转向，实际转动后根据前向射线测距决定行程，不先找猫或静止取景；逃跑完成后主动搜索并对准猫，等待追击结束再检查朝向。两分支完成回应后都进入现有的试探／观察／巡游后续决策。达到轮数的**那次触碰**改由独立三种结局概率决定；无触碰超时只直接结束互动。网页等待 Uno 确认 `SESSION_STOPPED`，再发送 `SESSION_START` 并从被中断的标签目标继续巡游。
5. “顶层决策与取景”面板显示当前输入、选定动作、依据和收尾朝向。日志分别记录 `SIM_CAT`、`DEBUG_INJECT`、Uno 的 `EVENT`、`UNO_TO_ESP32`、`TOP_LEVEL_DECISION`、`FACE_CAT_RESULT` 和底层 TX 命令，可导出 JSON 检查决策依据。

串口模式的巡游找标签和触碰后找猫都通过续发 `MOTOR` 命令旋转，摄像头发现目标后立即 `STOP`；对应侧超声波阻挡时等待空间腾出，再继续同一次搜索，超时仍不安全则结束寻找。捕猎回应进行中再次触碰会记录输入，但不会排队重启回应；声光探索中新的有效触碰会即时换成下一种声光节奏。逃跑按当前视觉方位或触碰开关方向计算初始转角；转动完成后重新射线测距，绝不提前查询其他朝向的净空。固件须先收到 `SET_GEOMETRY`；尚未接入实体视觉观测，网页自主决策只用于本地或 V5.6 测试模拟。空板准备按钮会设置页面轮径与轮距，轮距留空时填入名义值 120 mm。实际接上驱动后请实测并重新设置几何参数。LIVE 模式的左右避障来自真实超声波，前方需要真实 ESP32 摄像头通过 `CAMERA_FRONT` 提供读数；本网页**不会**把模拟画面的摄像头数据送入 LIVE。真实摄像头尚未接入时，固件拒绝前进。DRY_RUN 使用模拟输入；两种模式共用 Uno 的运动和安全判断。Uno 重启时决策运行停止，需重新确认连接与几何参数。

## ESP32 层的互动动作

### 顶层状态与 Uno 会话命令

| 当前状态 | 触发条件 | 下一状态 | 必须完成的动作或依赖 |
| --- | --- | --- | --- |
| 待命 `IDLE` | 点击“启动巡游决策” | 巡游 `PATROL` | 向 Uno 发送 `SESSION_START` 并等 `SESSION_STARTED`，然后寻找路线标签 |
| 巡游 `PATROL` | Uno 报告触碰按下，或收到一次性 HTTP 指令 | 互动 `INTERACTION` | 保存当前巡游标签；触碰与 HTTP 指令进入彼此独立的决策分支 |
| 互动 `INTERACTION` | Uno 首次回报触碰按下 | 互动 `INTERACTION` | 一轮互动只抽一次声光探索／捕猎分支。探索触碰立即启动不同的声光节奏；捕猎触碰抽装死／慢逃／快逃，逃跑须等触碰开关松开，且遵守 Uno 运动安全检查。连击合并窗口只用于把随后快速触碰算作同一轮，不延迟首次回应；每次按下仍记为证据 |
| 互动 `INTERACTION` | 触碰回应启动失败，包括找不到猫、无法对准或安全中止 | 收尾 `ENDING` | 立即停车，强制选择“直接巡游”，不抽取倒下结局，不等待下一轮决策 |
| 互动 `INTERACTION` | 新一轮抓住触碰达到轮数 | 收尾 `ENDING` | 在触碰当下抽取直接巡游、安静装死或声光装死；装死期间停车，不能先逃跑再装死 |
| 互动 `INTERACTION` | 无新触碰超时或会话上限 | 收尾 `ENDING` | 直接结束互动，不抽取装死结局 |
| 收尾 `ENDING` | 倒下反馈完成或选中直接巡游，且 Uno 确认 `SESSION_STOPPED` | 巡游 `PATROL` 或待命 `IDLE` | 原本在自动巡游则先发送 `SESSION_START` 重新开放 Uno 运动，再继续原目标标签；单独触碰则回待命 |
| 任意运行状态 | 人工停止 | 待命 `IDLE` | 立即发送 `STOP` 停车并取消当前自动决策 |

`INTERACTION`/`ENDING` 是网页模拟 ESP32 的顶层状态；`SESSION_START`/`SESSION_STOP` 是发给 Uno 的底层命令。`SESSION_STOP` 会锁住后续运动，不能用它表示“允许继续巡游”；恢复运动必须再发送 `SESSION_START`。协议没有 `SESSION_END` 命令。

下面是独立决策系统可能输出的行为，以及网页代替 ESP32 执行这些行为时发送的命令。**行为名称本身不会发给 Uno**；日志会显示拆解后的 `DRIVE`、`ROTATE`、`STOP` 等底层命令。速度、距离和停顿时长是初始参数，需要之后用实体电机标定。

| 网页动作 | 输入与拆解方式 | 动作后的处理 |
| --- | --- | --- |
| 固定路线巡游 `PATROL` | ESP32 模拟层按 A/B/C/D 标签顺序读取模拟标签画面；仅按当前前向射线距离分段行驶；受阻时依据侧面测距真实转动，再测量、前进并重新搜索标签；抵达指定距离后扫描下一个标签 | 收到一次性 HTTP 指令或 Uno 触碰时中断巡游；无安全绕行路径则暂停；巡游本身不找猫、不计互动时长 |
| 声光探索 `EXPLORE_SOUND_LIGHT` | 一轮互动抽中探索分支后，每次有效触碰选一种不同的 LED 常亮或闪烁节奏，同时发送 `BEEP`；接触中不启动轮子 | 松开后寻找并观察猫，再进入与捕猎共用的后续决策；没有接触后按同一超时条件结束 |
| 捕猎回应 `ATTACK_RESPONSE` | 抽中捕猎分支后，按装死／慢逃／快逃概率回应，并独立抽取触摸时声光反馈。抽中反馈即在接触中闪灯和鸣叫，不启动轮子；抽中装死则立即停车倒下；逃跑在松开后直接规划远离猫且有净空的路线 | 逃跑后停车并主动搜索、对准猫；等待追击后再次寻找并面向猫静止观察。找猫失败会显式记录；安全中止时停车并退出互动 |
| 缓慢接近 `SLOW_APPROACH` | 模拟摄像头先找猫并对准；按调试距离和 PWM 前进，默认 9 cm、PWM 95 | 停下，重新找猫并对准 |
| 走停试探 `PROBE_APPROACH` | 猫主动触碰后的独立后续概率，或机器人主动找猫时的远处概率选中且各自冷却结束；对准猫后以调试 PWM 分三段前进，默认 3、4、3 cm | 猫离开视野时结束试探；收尾重新找猫并对准 |
| 快速前进 `FAST_FORWARD` | 较高 PWM 直行约 23 cm | 停下，重新找猫并对准 |
| 缓慢直线逃跑 `SLOW_STRAIGHT_ESCAPE` | 等触碰松开，利用当前视觉方位或触碰方向先转向，再测量前方净空，按调试速度和距离直行，默认 PWM 95、最多 26 cm。需先配置轮径和轮距 | 停下后搜索并对准猫；无安全方向不前进；逃跑动作被猫抓停时，等触碰松开后自动续跑一次，链路错误（如 `UNKNOWN_OR_INVALID_COMMAND`）最多重发 2 次 |
| 快速直线逃跑 `FAST_STRAIGHT_ESCAPE` | 同样不等取景，选远离猫且有净空的方向，默认 PWM 210、最多 26 cm | 停下后搜索并对准猫；抓停续跑与链路重发同慢速逃跑 |
| 被抓摇晃 `CAPTURE_WIGGLE` | 仅供手动演示，原地以较低 PWM 和短时间的 `TURN LEFT/RIGHT` 交替摇晃 | 停止后寻找并对准猫 |
| 机器人主动声光回应 `STAY_SIGNAL` | 机器人主动找到猫并对准后停车、闪灯 1.4 秒、蜂鸣 180 ms | 声光结束后再次检查朝向 |
| 结束互动 `END_SESSION` | 捕猎分支每次被抓住可按概率当场装死；两分支达到轮数的那次触碰都使用独立的三种结局概率。装死时立即停车，可安静或声光示意，等待猫实际离开或最长静止时间。无触碰超时与会话上限只直接结束 | 装死期间不再转向猫；其他收尾可面向猫静止观察。随后发送 `SESSION_STOP` 并等待确认，必要时重试或查询状态；确认后发送 `SESSION_START`，从中断的标签续巡 |

`SEARCH_CAT_START`、`SEARCH_CAT_STOP`、后续的对准猫动作，以及 `OBSERVE` 都属于网页模拟的 ESP32 执行流程；Uno 收到的是具体电机和停止命令。`SEARCH_CAT_STOP` 在“猫进入画面”时触发，对准猫是下一步。逃跑后寻找猫的上限为 360°，默认收尾超时 8 秒。若触碰默认 4 秒未松开或被 Uno 安全保护中止，网页停车并记录失败；若逃跑后找猫失败，会记录 `FACE_CAT_RESULT status=FAILED`，无法保证物理朝向。`SESSION_STOP` 停车并锁住 Uno 的后续运动；`SESSION_START` 才重新开放运动。两者均是底层协议命令。真实系统应由 ESP32 使用摄像头观测和触碰历史确定方向；网页只使用射线测距、接触检测、当前摄像头可见目标和编码器观测规划动作，ESP32 摄像头固件见 `esp32-host`，本页不自动接入。网页没有验证实体电机在低 PWM 下能否启动，也没有测量真实位移。

## 串口协议

网页发送一行 `CMD <id> <command>`，固件按行返回 `ACK <id>`、`DONE <id>`、`ERROR <id> <reason>`、`EVENT ...`、`DATA ...`。例如：

```text
CMD 12 DRIVE 20 120
ACK 12
EVENT MOTION_STARTED 12 DRIVE ESTIMATED
EVENT MOTION_DONE 12 ESTIMATED LEFT_PULSES=20 RIGHT_PULSES=20
```

示例支持的命令：`PING`、`SESSION_START`、`SESSION_STOP`、`STOP`、`MOVE FORWARD|BACKWARD <pwm> <ms>`、`TURN LEFT|RIGHT <pwm> <ms>`、`DRIVE <cm> <pwm>`、`ROTATE <degrees> <pwm>`、`MOTOR <left_pwm> <right_pwm>`、`LED ON|OFF|FLASH`、`BEEP <ms>`、`GET_STATUS`、`GET_DISTANCE`、`GET_ENCODER`、`GET_CONFIG`、`CAMERA_FRONT <CLEAR|BLOCKED|INVALID|cm>`、`SET_SAFE_DISTANCE LEFT|RIGHT <cm>`。正角度表示向右转。`MOTOR` 500 ms 内未续发会自动停止。模拟距离或角度结果标为 `ESTIMATED`。

串口连接模式下所有命令经统一写队列串行发出，相邻两行至少间隔 15 ms，避免突发压垮 Uno 的 64 字节接收缓冲；运动命令前的传感器同步（`CAMERA_FRONT`、`DEBUG_INJECT SONAR`）逐条等到 `DONE` 才发运动命令。配合 V5.2 固件的收发互不阻塞加固，可消除“逃跑指令被丢字节打碎成 `UNKNOWN_OR_INVALID_COMMAND`”的故障。运动命令遇到此类链路错误自动重发（日志 `MOTION_RETRY`），`SESSION_STOP` 无回执自动重试（日志 `SESSION_STOP_RETRY`）。

调试输入示例：

```text
CMD 13 DEBUG_INJECT TOUCH LEFT PRESS
CMD 14 DEBUG_INJECT TOUCH LEFT RELEASE
CMD 15 CAMERA_FRONT 12
CMD 16 CAMERA_FRONT CLEAR
CMD 17 CAMERA_FRONT INVALID
CMD 18 DEBUG_INJECT ENCODER 10 10
CMD 19 DEBUG_INJECT SONAR LEFT 45
CMD 20 DEBUG_INJECT SONAR RIGHT 50
```

这些是固件已实现的命令。完整参数、安全规则、引脚以及调试模式见 [Uno 固件说明](./firmware/README.md)。串口模式下，发送注入命令前先点“开启固件调试”；如果尚未接电机，再点“电机空转模式”。几何参数区需要填写实测轮距，固件才接受 `ROTATE`。本地 `SIM_UNO` 依旧只模拟协议，不执行固件代码。

## 串口连接

点击“连接 Uno 串口”，选择设备。网页使用 Web Serial、波特率 57600；请用支持 Web Serial 的 Chrome 或 Edge 通过 `localhost` 打开页面。连接后可移动场景物体测试传感器；持续场景注入仅在空板模式启用。LIVE 模式的前向摄像头数据源须由真实 ESP32 实现，本仓库目前只定义 Uno 接收协议和 HTTP 视频预览入口，没有实物摄像头算法或 ESP32 串口程序。ESP32-S3 后续可同时提供视频流给网页，并把图像识别得到的前向安全判定以 `CAMERA_FRONT CLEAR|BLOCKED|INVALID`（或经标定的厘米读数）送入 Uno；视频流本身不构成安全读数。

Uno R3 的 D0/D1 硬件串口与 USB 调试共享；Uno 的 5V TX 接 ESP32-S3 RX 需要电平转换。固件引脚分配和接线注意事项见 [Uno 固件说明](./firmware/README.md)。

## 串口场景移动与混合 IO

策略测试页提供与硬件页同步的 14 路物理 IO 开关，以及模拟未接输入开关。切换 IO 会停止策略，设置后重新启动。轮径默认 67.5 mm。

串口场景只用带校验的 MP 脉冲回报更新位置，运动中约每 100 ms 回报；不再按名义速度推进位置，也不在读数丢失时切换回虚拟速度。输入关闭或没有脉冲时，串口画面不会凭命令移动。纯虚拟电机使用 Uno 生成的虚拟脉冲；纯本地模拟仍由 MockUno 更新。位置按 67.5 mm 轮径、20 脉冲/圈换算，暂不计算打滑；相等轮速按直行/原地转向处理，避免左右脉冲异步造成航向晃动。逐帧平滑只影响绘制。

## V5.6 低流量串口与丢帧恢复

主固件和网页统一 57600 波特，启动握手 READY UNO_CAT_V5.6。必须重新烧录主固件并刷新页面后连接；独立 SimpleMotorTest 仍为 115200，不适用于网页协议。

网页在线上使用 C id CF / GT / DI S L|R 等短指令，并加 *HH CRC-8（多项式 0x07）；缺少或校验失败的 C 帧不执行。手动 CMD 长指令仍可用。ACK、运动开始/完成/中止分别缩短为 AK / MS / MD / MA，均带 CRC；网页验证后还原成人可读日志。删除两侧注入测距的冗余 EVENT 回显，保留 ACK/DONE。未增加重复状态同步、运动状态轮询或无条件重发动作。硬件卡片每 250 ms 刷新，运动开始不额外触发整批刷新；运动脉冲另用短 MP 帧回报，不增加重复 STATE 同步。

修复：开始回报乱码时，可用已有 ACK 激活动画；若开始与 ACK 均丢失，最终完成回报仍能用对应待执行命令和起始位置校正位移，而不会不断重复同一路段。若所有有效运动回报都丢失，无法保证连续画面；不会把发送命令本身当作硬件已执行。关键运动帧有校验，其余遥测仍使用原协议，软件容错不能消除供电噪声。导出日志补充 IO 开关、最后的遥测读数及协议版本。

## V5.6 持续开关控制

前进和后退在串口模式下使用 MOTOR 开启、KEEP 每 200 ms 续期、STOP 关闭，由电脑根据 MP 累计脉冲决定停止；距离控制需要真实电机对应的真实编码器。续期不切断引脚，也不重置运动编号或脉冲基准。相同 MOTOR 命令同样只续期。通信中断超过 500 ms、电机堵转、障碍和触碰仍由 Uno 停止。电脑超过 750 ms 没有有效运动反馈，会停止距离动作。

巡游取消每 12 cm 必停的上限，持续接近标签，仍会因标签对齐、障碍或停靠而停止。默认提前停止余量 3 cm，可在几何参数区调整。硬件卡片正/反转按钮改为开/关，再按同方向按钮关闭该轮，可组合左右轮；总停止按钮关闭两轮。
