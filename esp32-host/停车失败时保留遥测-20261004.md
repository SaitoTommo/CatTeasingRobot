# 2026-10-04 ESP 0.26：停车失败时保留遥测

log32 ESP0.25：STOP101未确认后，92913ms进入自动恢复。三轮STOP104、106、108均只收到UART_LOOPBACK，没有对应MOTOR_STOPPED，96587ms失败退出；所以配置读取和会话重新同步根本没有执行。97790ms再次停车未确认后，GET_TELEMETRY114在99792ms被TX_BLOCKED；GET_TELEMETRY115在106793ms同样被拦截。界面全部遥测过期是此发送保护的结果，不能据此判定所有传感器故障。

108826ms切到SIM_UNO时，108827ms仍发送了原UART模式排队的物理STOP116，108838ms得到真实停车确认；之后111037ms切回UART，STOP128同样确认。恢复发生在切回真实UART之前。两端USB都有真实回复。模式切换源码没有重新begin硬件UART，与自动恢复的差异不能简单称为硬件串口被重初始化；时序和外部物理链路根因仍待查。不要把先前回显当成确认。

0.26：停止未确认保护只允许新的STOP，以及严格匹配的GET_TELEMETRY、GET_CONFIG、PING只读查询。只读查询不会清除stopPendingId、stopUnconfirmed或重启停车计数；运动、SESSION_START、配置写入等仍禁止。停车确认等待期间仍优先停车，失败后的只读遥测才放行。若物理接收仍回显或损坏，界面仍须显示无新读数，不能伪造有效值。

原生检查验证只读白名单及尾随字段、非查询伪装被拒绝，全部现有策略818项、扫描259项、连续互动252项、PWM/设置2640项和视觉/CRC检查通过。该修复恢复诊断查询通道，未证明自动恢复可以消除UART_LOOPBACK。
