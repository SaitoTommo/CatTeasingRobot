# ESP0.20：猫触碰找猫流程简化

依据用户在2026-10-04的最新要求：猫触碰后，声光回应是独立并行状态；找猫主流程收敛为“转停搜索 → 原地停车复核 → 执行行为”。本次仅修改ESP，Uno继续使用V6.9。

## 日志16的实际问题

原始文件保存在 `evidence/scan-handoff-20261004/esp32-log(16).json`。

ESP0.19导出时为CAT_CHECK，识别帧2098，motorId=0、motorRunning=false。日志416607ms至421192ms反复执行 CAT_CHECK → ALIGN_CAT → WAIT_STOP → CHECK_ALIGN → SETTLE → CAT_CHECK；417148、418307、419537、420552ms分别发送ROTATE 20.3 255。原请求PWM52被最低PWM255提高。每次检查后继续对准旋转，导致视觉上像复核期间一直在动；现有日志没有证明CAT_CHECK/SETTLE状态内另发了运动命令，也不能证明物理惯性已完全停止。

## 简化后的猫触碰流程

1. 首次触碰开启互动。独立抽取触碰声光，概率沿用 `touchFlashPercent`，网页命名“触碰时并行声光概率”。停车确认后声光启动，不等待其结束，也不把声光当作主流程分支。按钮仍按住时保持停止，松开后开始扫描。
2. `SEARCH_CAT_ACTIVE`：Uno旋转一小步、停车、等待停稳、VQ请求新帧、ESP回报VR。未找到则下一小步；首次找到并收到有效SD后，确认STOP，进入唯一的 `CAT_CONFIRM`。
3. `CAT_CONFIRM`：先取停车后的两次编码器样本并满足最低等待/安静窗口；再原地等待 `catConfirmWaitSeconds`（默认5秒，网页0–30秒可调）；最后仅请求一次等待结束后的新帧。停稳、定时等待、新帧检查均在同一个主状态，快照 `confirmationStage` 仅说明当前检查条件。整个复核不发送ROTATE、DRIVE、MOTOR或SR，不进行居中对准。
4. 新帧检测有效且仍有猫，才抽取装死/探索/逃跑。新字段 `catConfirmPreyPercent=20`、`catConfirmExplorePercent=20`，其余60%逃跑。默认比例是未收到第二个概率偏好答复后的暂定值，网页可调；两者合计不能超过100%。重复触碰不重抽主行为。逃跑才进入独立的转向远离、直行状态；探索的后续观察也复用原地复核，避免ALIGN_CAT循环。
5. 复核新帧未找到猫：恢复转停搜索，沿用剩余扫描预算。无有效编码器样本或新帧超时：安全退出，不因等待到期假定猫存在。旧代次帧/SD不能重新启动动作。

机器人HTTP主动找猫、标签巡游和分段接近保留原有入口与控制。本次简化针对猫触碰互动，未改这些独立行为的概率或路线。

## 声光与动作的关系

声光计时通过独立 `touchSignalUntil` 维护，网页显示“并行触碰声光”。运动停车不必结束它；FAULT、操作员停车、互动结束和装死强制关闭。若准备扫描时清理了尚未发送的声光队列，只补发剩余时间，不能延长原计时。探索声光属于复核后的选中行为，与触碰反馈区分。
