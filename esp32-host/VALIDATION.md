# ESP32 实机验证记录

日期：2026-09-30，设备：用户指定 COM11，esptool 确认 ESP32-S3 revision v0.2、8MB PSRAM。

## 已验证

- 原网页及新增协议/路线测试共 65 项通过。
- 集成板载视觉、状态机、HTTP 流的版本编译通过，程序约 3.66MB，占最大应用分区 44%。
- COM11 烧录完成，Flash 校验通过。
- 实际启动日志：`CAMERA init=0 psram=8388608`，证明本次摄像头初始化成功。
- 栈修复后的最终源码编译、COM11 烧录及 Flash 校验通过：程序 3,659,430 bytes（44%），静态 RAM 77,832 bytes（23%）。
- `serial-smoke.py` 实机通过：USB JSON、六节点含重复 ID 的路线、非法路线拒绝、CRC 错误拒绝、标签目标推进、反馈缺失停车、摄像头持续出帧（106 → 124）。结果见 `serial-smoke-result.json`。
- `vision-smoke.py` 连续约 77 秒通过：仅预览 35 秒、标签 12 秒、猫 15 秒、双识别 15 秒。帧序号 489 → 873，三个识别模式均返回板载观测；本次末帧推理耗时分别约 187/222/399ms。没有测试实物检出正确率或长时间温升。结束后已关闭推理。

## 已发现与修复

- 中文构建路径令 ESP32 链接器输出失败：改用英文临时构建路径。
- 初版运行栈溢出：日志为 `Stack canary watchpoint triggered (loopTask)`。addr2line 映射到 `readLines()`、`loop()`，两个 4096-byte 局部 Input 缓冲占用默认任务栈。移出栈、控制栈改成 16KB；类型移入头文件以避开 Arduino 自动函数声明顺序。
- 初版默认同时运行两种视觉推理：改为上电仅预览约 5fps，按需选择标签/猫/两者，每次检测后休息至少 1.5 秒。未测得温度，不能将此前重启归因于过热。
- 灯熄灭观察：官方资料明确未接电池时红色充电灯约 30 秒熄灭是正常状态。未确认用户观察的具体灯、USB 断连或电源异常。

## 当前未验收

- 用户要求隔离 Wi-Fi：已烧录 `WiFiMinimal` 替代完整应用，只运行 STA 和串口；40 秒监测仍未连接，原因码 201（NO_AP_FOUND）。当前板上是最小测试程序，HTTP/视频/控制功能暂时不运行；完整源码可重新烧录恢复。

- 已按用户提供的笔记本热点名称/密码经 COM11 写入开发板 NVS。35 秒连接检查仍为 `stationIP=0.0.0.0`，未连接成功；待确认笔记本热点开启、2.4GHz 与天线连接。凭据不存入仓库。
- 电脑网页启动脚本用端口 18766 验证了新建服务、页面与模块可访问、已有服务复用；随后仅结束该测试创建的 PID。双击 BAT 的浏览器操作未做人工验收。

- HTTP 视频尚未实机验收：两次连接热点尝试均未获得 DHCP 地址，扫描未见 ESP32-CatHost；串口状态仍报 AP=192.168.4.1。待确认外置天线接好后继续测试。两次均恢复原 Wi-Fi。
- 栈修复后短时运行已通过；识别任务长期稳定性、温度与电源情况未测量。
- 猫及贴纸真实识别质量由用户验证，当前没有实物正确率结论。
- Uno UART 接线、物理电机/编码器、几何标定和整机巡游/互动未验收。JavaScript 下位机测试不能替代这些检查。
- 单目前向地面外观检查是原型，未验证实车安全，不能当成可靠深度测量。

脚本：`serial-smoke.py` 仅在 SIM_UNO 测 USB、路线、CRC 和反馈缺失停车；`vision-smoke.py` 测任务运行而非识别准确率；`http-smoke.py` 验证 JPEG 和多帧 MJPEG；`test-hotspot.ps1` 会暂时切换 Wi-Fi，等待 DHCP，finally 恢复原连接。电脑 HTTP 检查绕过系统代理。
