# 猫识别帧率实验分支

基线：已由用户现场验证并提交的 ESP0.29，Git f40bf52。分支 cat-vision-fps-bench，固件 ESP32_CAT_HOST_0.29_FPS_BENCH。Uno 不修改。默认关闭测试，原控制网页、路线、参数、动作测试和停车/通信恢复逻辑保留。

在原页面增加性能区域，开启后静止及运动时持续识别猫。原预览区域改为识别原图加浏览器绘制的猫框，JPEG 与响应头 X-Vision-Result 在同一互斥锁下复制，保证框和图片属于同一帧。关闭测试恢复原实时视频。位置为原图像素坐标，同时返回猫框、置信度、图像尺寸和帧编号。

识别完成后的额外空隙可调 0–5000ms；采集后的额外空隙可调 0–2000ms。两者为运行期参数，不修改保存配置。零表示取消对应固定等待，仍等待新帧并让出至少一个调度 tick；没有重入推理或积压旧图。非测试模式保留原采集200ms、连续推理启动间隔350ms。状态机请求帧优先，并保留其新帧/scanId/stepId/generation规则，不受实验空隙限制。

测试期间原策略需要标签时同帧执行猫和标签，原策略需要地面检查时继续计算地面结果。提供给策略的连续结果保留原模式和有效性，不把运动测试的猫框冒充停车识别；请求帧仍按原票据处理。BOTH模式整次处理耗时含标签工作，猫模型耗时单独列出。

逐次记录：编号、帧号、解码/模型初始化、猫模型推理、整次处理、相邻启动间隔、上次完成到本次启动的实际空隙、采集到完成的图像年龄。毫秒计时；整次处理包含预处理/后处理和地面/标签工作，不包含HTTP图像传输。首轮模型初始化不剔除。

网页分别展示整次处理与猫模型推理的平均、中位数、P95、最小、最大耗时，并根据设备启动间隔计算识别频率。P95为最近邻秩定义：升序第ceil(0.95*N)个样本。ESP保留最近128次，浏览器保留最近20000次并可导出CSV；超出设备缓冲的丢失记录明确计数，不能把浏览器图片刷新率当作识别帧率。换间隔比较时先“清空并重新计时”。

使用：保留原串口/巡游/主动找猫/手动测试操作；开启性能测试，在静止与运动条件下分别比较200、100、50、0ms。若要解除原采集速度限制，采集空隙也需设零。观察CPU/堆、网页请求失败与Uno连接，零空隙会增加实际系统负载。
