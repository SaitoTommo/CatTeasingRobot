# ESP V0.17：启动巡游不再要求扫描能力声明

用户明确当前只配对新版Uno，要求取消SCAN_V1能力门槛，不再增加旧固件兼容确认步骤。本次删除start/resume里scanCapable=false就拒绝的分支；无须手动PING。启动仍直接执行原有STOP确认→GET_CONFIG→SESSION_START→SC→SR流程。scanCapability仅作收到过声明的诊断信息，不影响启动；不会增加自动探测握手或等待。

原始证据start-capability-gate-20261003.json：串口/STOP/手动测试正常，限时测试结束调用stop产生operator_stop，巡游启动多次被未收到SCAN_V1声明拒绝。本次针对启动阻挡，不修改正常停止的FAULT分类。实际扫描配置和开始扫描回复继续用于执行流程，非旧固件能力检查。

自动化：实际policy.cpp策略579项，新增真实UART、没有PING/READY/能力事件时start与resume都能完成停车/读取几何/开启会话/配置扫描并发SR；235扫描核心、2603PWM/参数、视觉门控和线路校验通过。保留现有SC/SR重试，不新增普通动作重试。Uno保持V6.8，NVS参数不变。

用户验收：刷新后确认ESP32_CAT_HOST_0.17，选择Real UART后直接启动巡游，不必点PING，展示46/40多轮并导出日志。能力字段false也不应再出现旧的SCAN_V1 capability required拒绝。UI与运动测试由用户完成。
