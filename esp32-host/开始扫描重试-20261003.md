# ESP V0.16 / Uno V6.8：开始扫描有限重试

用户要求：开始扫描遇到可重试校验错误立即重发；一直无回应则实际发送后100ms重发，首次之外最多重试3次。SC配置继续采用前版规则，不扩展普通运动命令。

证据：scan-start-envelope-failure-20261003.json中SC174配置成功，57812ms发送SR175，57821ms收到ERROR 0 BAD_ENVELOPE，未收到175的AK/MS；60314ms旧程序motion start not confirmed。心跳和遥测正常，不能仅凭日志归因物理接线或SoftwareSerial时序。

实现：SR首次参数（包含实际PWM）冻结；重发保留相同命令编号、generation、方向、脉冲和预算，CRC重新生成，不占用新编号。收到匹配或无编号BAD_CHECKSUM/BAD_ENVELOPE立即入队重发，不额外等待100ms；串口原有最小发送间隔仍保留。实际发送回调起算100ms，排队未发不计超时；重复错误在重发排队期间不叠加。最多3次重发，第四次发送仍失败/100ms未确认则STOP并给出最终原因。ACK/MS/MP/VQ等有效对应回复按原协议确认，不再重试。STOP/触碰/新流程清队列并清扫描ID；真正新一轮清重试次数。等待SR确认时暂停普通遥测。语义拒绝、障碍、触碰锁定不重试。

Uno补丁：解析合法SR且通过session/touch锁后，若编号与generation匹配现有扫描，直接补ACK（终态允许补发SD），不重新进入运动启动门禁、不推进阶段、不改变步数、已用脉冲、时间或基线。扫描核心本来已有同身份begin防重复，本次把完整解析器的重复请求路径明确提前，避免侧距变化影响同一请求的补确认。没有改VR或普通DRIVE/ROTATE的重试。

版本顶部注释、HTTP/READY分别V0.16和V6.8；两份Uno源同步。默认/已保存参数不变。

用户验收：两块板上传完成后网页选择Real UART，PING确认SCAN_V1，展示46/40多轮；日志出现SR校验错误时应立即有SCAN_START_RETRY，并保持同一个编号及相同payload。无启动回复间隔100ms，最多3次重发；收到对应确认后继续，失败用尽停车。不要以断开运动通信来注入故障；错误和超时注入由自动化测试完成。

验证：原生实际ESP策略557项、Uno共享扫描核心235项、PWM/设置2603项、视觉门控/实际接收校验、网页18项全部通过。SR重复请求在TURN/SETTLE/WAIT_VISION/NEXT/TERMINAL均保持状态、步数、预算和时刻；ESP覆盖未发出不计时、99/100ms边界、立即错误重试、队列去重、同编号冻结PWM、ACK/MS停止重试、三次重试用尽、停止取消、锁定拒绝不重试、不匹配编号忽略、下一扫描清零。测试最初沿用旧遥测预期，在配置成功而SR未确认时错误要求恢复轮询；现已改为SR确认后恢复。编译Uno32206/32256字节、RAM1379；ESP3721018/8257536字节、RAM78832。
