# 2026-10-05 网页 Uno 模拟器与连接稳定性

## 计划

1. 对齐当前 Uno 的 TB v1 遥测、CRC、运动和 SCAN_V1 协议。
2. 在实际 ESP 网页验证完整显示、数值变化、视频并行和持续刷新。
3. 在网页保持打开时测试并发，保存数据并更新项目日志对话。

## 已查明的差异

旧 `esp32-lab.mjs` 只回报左右超声的旧格式数据，其他行为空；没有 SCAN_V1，也缺少新视觉观测的有效性、帧号和 generation。旧界面的“连接”测试不能替代完整数据验收。

新 `FirmwareUnoSimulator` 复用场景物理模型，并按固件线协议发送 50 字节、三段 CRC 的 TB v1。ESP 原子展开为 13 行传感器和输出回报；支持 AK/MS/MP/MD/MA、SC/SR/VQ/VR/SD、配置回读、扫描停稳、过期视觉拒绝及重复请求去重。物理 IO 默认关闭，编码器和输入来自模拟场景，不能视为真实硬件测量。路线从 ESP 读取，保留 `[46,40]`，不自动覆盖已保存配置。

本地服务增加固定指向 `192.168.137.130` 的 HTTP 模拟桥，绑定 `127.0.0.1`。写入限定操作并携带 `expectedMode=SIM_UNO`；固件执行时检查模式，`uno_batch` 只在 SIM_UNO 且非物理来源时接收。它用于不支持串口选择的浏览器环境，USB 通路仍保留。

## 实际网页发现及修正

- 真实网页已显示 13 项遥测。一次 300ms 模拟前进后，左右编码器均显示 4 脉冲；DRY_RUN、IO 掩码 0。仅验证模拟链路。
- 逐行 HTTP 回报曾发生缺段；改为同一浏览器任务内汇总、微任务立即批量发送，避免后台计时器延迟一秒。
- 浏览器后台计时会减慢场景步进；按固定短步补足场景时间。SIM_UNO 遥测请求间隔上限改为 1000ms，真实 UART 的策略间隔保持原值。
- 实测有 TCP reset，而 Wi-Fi 断开计数仍是 0。状态 GET 允许两次各 2 秒的只读尝试；重试成功维持数据显示，两次失败仍显示断连并禁止控制。操作 POST 不自动重试。
- 模拟桥日志上限由 160 降为 40，并取消每次写入前重复取整份状态，减少临时内存和 HTTP 请求。

## Socket 边界

当前预编译 SDK `CONFIG_LWIP_MAX_SOCKETS=16`。0.31–0.33 为控制客户端 8、视频客户端 2，两个 HTTP 服务内部各占 3 个 socket，因此客户端总预算是 10。16 不能解释为 16 个可同时占用的网页客户端；只改宏不会扩展预编译 lwIP。早期真实网页负载最低 heap 曾到 544 字节，不能据此宣称支持无限并发。

用户随后要求视频预留 3–4 路，并询问能否减少内部开销和并发请求。核对本机 ESP-IDF 5.5.5 头文件及[同版本官方实现](https://github.com/espressif/esp-idf/blob/v5.5.5/components/esp_http_server/src/httpd_main.c)后，确认每个服务实际创建监听 TCP、控制发送 UDP、控制接收 UDP 三个内部 socket，不能仅改一个预留参数减少。

0.34 改用单个 80 端口 HTTP 服务，共享 13 个客户端额度；视频最多 4 个异步长连接，满载时另 9 个用于 API，内部 3 个，合计 16。`/stream` 替代 `:81/stream`，网页和模拟器同步更新；现有外部视频客户端需要更换地址。API 可以临时使用空闲视频额度，视频长连接不会被 HTTP LRU 清除。这个配置上限不等于实际有 13 个请求在同时执行；API 仍由 HTTP 线程处理。

原视频处理器在 HTTP 线程内循环不返回，第二个视频连接无法得到响应。新处理器创建异步请求副本并立即返回，由一个工作任务把共享 JPEG 发给最多四个客户端；失败时完成异步请求并释放连接。网页所有状态、流程、识别原图和性能读回共用一个读取队列；读操作一次只有一个在途，操作 POST 不排在这个队列后面。

### 最终部署与真实页面观察

0.34_SHARED_HTTP 已经 COM11 仅应用上传，hash 验证成功；编译程序 3774906 字节，静态 RAM 85352 字节。分区一致、保存配置保留。证据：verification.json、upload.txt、shared-after-state.json、served-final-page.html。

电脑模拟器 GET 状态与 POST 回报/观测共用 SimHttpTransport，一次仅一个 HTTP 请求在途（包括 JSON 读取）；仅替换排队的旧视觉观测，命令和遥测不丢弃。串口通路保留。实际浏览器发现 fetch 作为对象成员调用会 Illegal invocation，已用函数包装保持浏览器正确调用方式；重载后成功连接。

最终三路额外视频加网页一路，180 秒中每个额外客户端 HTTP200、805 帧、约 2.86MB，首字节 157–175ms，没有提前结束或流错误。四路满载时第五路返回503。真实网页120次采样跨度178717ms：每次均13行、视频320像素宽、整页断连0次；数据过期5次，采样最大5521ms，最后40次未过期、最大2404ms。数据保持显示成立，高压下持续新鲜尚未成立，不是长期稳定性结论。
