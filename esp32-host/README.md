# XIAO ESP32-S3 Sense 上位机

分支 `esp32-sense-host`，基线 `9217cc9`。关键阶段分别提交，保留现有 Uno 测试台。

## 连接

双击仓库根目录 `启动ESP32测试网页.bat`，自动启动本地服务器并打开 ESP32 页面；已运行则复用。端口被旧版本或其他服务占用时提示关闭对应服务，不自动结束进程。启动日志在忽略版本管理的 `esp32-host/vendor/web-8765*.log`。PowerShell 也可运行 `./esp32-host/start-web.ps1`；`-NoBrowser` 只启动服务，`-Port 8766` 可选择其他端口。它启动的是电脑测试网页；开发板调试网站随固件上电启动。

从原测试台打开“ESP32 实机上位机”，或访问 `http://localhost:8765/esp32-lab.html`。USB 使用 115200 波特，选择 COM11；网页模拟 Uno，ESP32 接收观测并运行决策。切换 UART 后不接受模拟输入。

开发板创建热点 `ESP32-CatHost`，密码 `catrobot32`。调试页 `http://192.168.4.1/`，HTTP MJPEG 流 `http://192.168.4.1:81/stream`。调试页可配置 2.4GHz Wi-Fi；热点保留，站点 IP 在状态中显示。

2026-10-01 接好外置天线后，完整固件已连接笔记本热点，当前地址 `192.168.137.22`；HTTP 页面、Uno 收信日志和视频解码已实测通过。IP 可能改变，以实时状态为准。电脑页面连接 USB 后会自动填写 stationIP 对应的视频地址和调试页链接。

也可连接笔记本移动热点：开启 2.4GHz 热点并接好开发板外置天线，通过 USB 或板载调试页保存热点信息。连接成功后使用状态里的 `stationIP` 访问 `http://<stationIP>/` 和 `http://<stationIP>:81/stream`；电脑测试页的视频地址也改成该流地址。固件重启会读取已保存配置自动连接。`http-smoke.py --host <stationIP>` 可验证此网络上的视频。

真实 Uno UART（0.5）：ESP32 D6/GPIO43 TX→LV4→HV4→Uno D12 软件接收；Uno D1/TX→HV3→LV3→ESP32 D7/GPIO44 RX，共地，57600/8N1。Uno D0只保留给USB串口桥。蜂鸣器移至Uno D13，LED使用ESP板载GPIO21；完整接线见[当前接线表](../SOFT_UART_WIRING.md)。USB控制和ESP UART是独立入口。先验证协议，再验收实体运动。

## 编译和烧录

旧版曾使用 `./build.ps1 -Upload -Port COM11`；当前请在本目录运行 `./build.ps1` 仅编译，使用 XIAO ESP32-S3、OPI PSRAM 和 `max_app_8MB` 分区。脚本保留完整猫检测模型，并将 `ESP32CatHost/debug_page.html` 无损 gzip 压缩为内置网页头文件；网页由浏览器自动解压。编辑网页后运行 `node ./generate-debug-page.mjs`，Arduino IDE 直接编译前也需生成头文件。编译失败时不自动烧录。

Arduino IDE 中对应选项：Board 为 XIAO_ESP32S3，PSRAM 为 OPI PSRAM，Partition Scheme 为 Maximum APP (7.9MB APP No OTA/No FS)。默认 8MB 分区的应用槽只有 3,342,336 bytes，不能把这个应用槽限制当成开发板的总 Flash 容量。当前应用不使用 OTA 和文件系统；NVS 配置区保留。不要使用整片擦除或合并镜像覆盖配置区。

## 路线

`route` 是有序 AprilTag ID 数组，例如 `[7,42,2,100,7]`，按顺序循环。支持 1–128 个节点，可重复访问；tag36h11 ID 范围 0–586。停止策略后保存，存于 ESP32 NVS，重启回读；上电不自动运动。

巡逻寻路使用独立转速：`patrolSearchPwm=45`（搜索标签）、`patrolAlignPwm=30`（对准标签），范围均为 30–150。电脑 USB 测试页和开发板调试页均提供“巡逻转向速度”输入框：停止巡游 → 修改两项 PWM → 保存 → 查看“板上当前值”确认 → 重新启动测试。保存后重启保留；读取实际配置后才允许保存，旧固件缺少参数时提示更新。旧保存配置没有这两个键时自动使用新默认值；原 `searchPwm`、`alignPwm` 继续用于互动中的找猫/对准，互动逃离及直行参数保持原值。降低 PWM 可减少两帧观测间的转角，但不保证消除纠偏摆动；实车需确认低 PWM 能稳定启动。

## 版本与验证

- 通信阶段：USB JSON 行、UART CRC、HTTP 调试页、独立流服务器、网页 JavaScript Uno 模拟入口。网页 65 项测试通过；此阶段策略/视觉文件为下一阶段接口，尚不提供识别或自主巡游。
- 已接入板载 ESPDet-Pico 猫检测、完整 tag36h11 识别，以及本地巡游/互动状态机。默认仅提供约 5fps 预览，不运行推理；在网页选择“只识别标签”“只识别猫”或“两种识别”。每次检测后休息 200ms，两次检测启动至少间隔 350ms，上电重新回到仅预览。实际观测周期包含推理和队列耗时；2026-10-01 各模式约 12 秒实测分别为标签 2.12Hz、猫 2.21Hz、双识别 1.49Hz，长期稳定性仍未验证。
- 状态机支持按路线搜索/对准/接近标签、编码器 360° 搜索上限、750ms 无有效脉冲反馈时发送 STOP、四区触碰、声光探索、捕猎逃跑、主动 HTTP 找猫、三段试探、装死等待及会话关闭/重开确认。0.10 已取消 KEEP；ESP 只在启动车轮、改变速度和停车时发送 MOTOR/STOP。距离停止使用 Uno 确认的几何参数；实体模式不能以模拟值补充缺失观测。
- 实机检查记录在 `VALIDATION.md`。首次烧录后发现控制任务栈溢出，已将两个 4KB 缓冲移出栈并增加任务栈。编译、启动、视频和识别质量分别记录，不把编译成功等同于实物验收通过。

### AprilTag 纠错内存评估（2026-10-01）

当前 `tag36h11` 使用 0 位纠错。目标 ESP32-S3 编译器确认 `quick_decode_entry` 为 16 字节；按本仓库 `quick_decode_init` 的容量公式，0/1/2 位纠错的码表分别为 28,176 / 1,042,512 / 36,544,272 字节。历史双识别日志中 PSRAM 最低剩余 6,606,424 字节，且固件已配置大块 malloc 使用 PSRAM。1 位纠错在容量上可行，2 位超过 8MiB PSRAM 总容量。此评估没有开启纠错；历史剩余总量不等于当前最大连续空闲块，开启前后仍需验证分配成功、峰值剩余和识别耗时。纠错仅容忍标签编码位读错，不能替代标签四边形检出。

## 前向标定与边界

地面外观检测路线来自先前的单目地面/障碍研究讨论，相关论文引用与当前简化范围见 [前向视觉研究依据](./FRONT_VISION_REFERENCES.md)。当前实现不包含论文中的 IPM、MRF 分割或距离估计；分块数量与阈值是项目参数。

前向默认 `INVALID`；视频可见不代表可前进。原型提供地面外观参考：停止策略，固定实车相机，用 15cm 标尺对应图像警戒区调整 `floorRoiTop`，确认当前警戒区是空地后点采集参考。中央一半视野、下部 ROI 分成 24 块，与参考灰度均值比较；接近的猫或外观变化返回 `BLOCKED`。这是定性外观检查，不是深度测距，同色障碍可能漏检，实车避障还需现场验证。相机高度、朝向、光照改变后重新标定。

只启用一种检测时，另一种视觉观测标为不可用。猫未检出、触碰松开都不证明离开；装死等待超时未确认则保持停车，现场确认后人工恢复。

## 板载 Arduino 调试网页（0.6）

首页用两个明显按钮显示 `Simulated UART` / `Real UART`，选中状态来自 ESP32 的实际模式回读；收到近期 Uno 回报才显示真实接收状态。切换模式停止策略与会话，并清空旧传感器、配置回读。

停止巡游后，可直接测试前进、后退、左转、右转和左/右轮各自正反转（PWM 1–255，时长 50–2000 ms），以及会话解锁、LED、蜂鸣器、PING、状态和配置查询。点击“开启测试：绕过全部避障”后，这些限时动作忽略前向标定、左右超声波和触碰；没有伪造CLEAR或测距值。开关仅作用于手动测试，自动巡游继续遵守避障；上电、模式切换、Uno重启后恢复避障。每次等待会话解锁，再发送 `TEST_MOTOR`；关闭绕过时先确认前向输入。结束后发送STOP/SESSION_STOP，CRC、会话锁、失速停止和急停保留。模拟模式只产生SIM_TX；真实模式通过GPIO43/GPIO44的57600 UART与Uno D12/D1通信，不接受HTTP模拟Uno回报。网页按钮发送成功只代表入队，执行结果看实际Uno回报。

Arduino 配置面板支持左右安全距离（5–100 cm）、轮径（20–150 mm）、轮距（50–300 mm）。ESP32 逐项等待 `DONE`，最后 `GET_CONFIG` 回读核对四项值。部分设置失败可能已改变先前项；请读取当前值核对。当前 Uno 只在 RAM 中保存这些值，Arduino 重启后恢复默认。轮径和轮距还须与 ESP 策略参数匹配。前向安全常量、触碰规则、电机最小驱动值等没有可写协议的限制会说明需改 Uno 固件，不生成无效设置按钮。

传感器面板独立显示超声波物理测距/控制值、编码器、四处触碰、电机请求/实际引脚输出、LED/蜂鸣器、前向判定、LIVE/DRY_RUN 及物理 I/O 掩码。每行单独计时，2.5 秒后标为过期；不会用其它新回报刷新旧读数。前向判定是上位机视觉输入，不是深度测量。板载网页复用 `hardware-telemetry.mjs`，构建时打包到 gzip，无外部 JS 请求。

## 构建命令

ESP32 0.11 配套 Uno 6.4：Arduino 配置面板和接口允许左右 1–100 cm；Uno 默认左右均 1 cm，仅有效新鲜测距严格小于阈值时执行超声波停车。无效或过期测距保持原样显示，但不触发超声波停车。前向判断仍只由 ESP 执行，停止确认、触碰、失速和 MP 反馈超时规则保留。新原因 SIDE_LEFT_OBSTACLE / SIDE_RIGHT_OBSTACLE 不再混入 SENSOR_INVALID。模拟 Uno 已同步该规则。此版本不代表长期串口失联已修复。

ESP32 0.10 配套 Uno 6.3：57600 不变，正常遥测每 2 秒请求一次，每次回三条 CRC 短帧和校验 DONE；收齐后原子更新 13 项显示读数。MP 编码器运动反馈改为 200 ms，独立于慢速遥测；ESP 超过 750 ms 没有有效 MP 仍发送 STOP。取消所有 ESP KEEP 定时发送，Uno MOTOR 没有续租截止时间。ESP 失联而无法发送 STOP 时，Uno 不会因为收不到续行自动停车，本地侧向、触碰、失速检查仍有效。限时手动 TEST_MOTOR 保留截止时间。真实巡游验收需用户操作，本轮上传后仅进行静止通信核对。

真实 UART 的 STOP 设置独立确认等待：收到匹配编号、CRC 正确的 `DONE id MOTOR_STOPPED` 才继续发送队列中的其它命令。每 300 ms 未确认时重发同编号 STOP，最多三次；仍未确认则清空后续队列并显示“停车未确认”，阻止新电机命令。显式新 STOP 可重新尝试，迟到的有效确认也可解除等待。清理普通命令队列不会清除已发出的停止等待。MOTOR 的 750 ms 反馈超时从实际串口发送时开始计时，避免排队等待 STOP 确认时误判。STOP 重发是停车确认恢复，不是续行。Uno 的 DONE 回报统一加 CRC。停止策略并不等于已经实测电机静止，停车确认表示 Uno 已执行关闭输出。

ESP32 0.9 在正常巡游按钮旁保留“前向避障”开关，需停止后切换，以板上配置回读为准，保存后重启保留。默认开启。关闭时跳过 ESP 的前向外观门禁，不改变 `frontCalibrated` 或参考图。前向判断和 STOP 停车指令由 ESP 决定；Uno 6.2 不再执行前向门禁，CAMERA_FRONT 仅保留兼容回读，正常控制不再周期发送此指令。标签新鲜度、左右超声波、触碰、失速和通信停车继续有效；不会自动切换 DRY_RUN/LIVE。

车轮架空固定的标签流程测试：选择 Real UART，确认 Uno 状态为 LIVE；在路线输入框保存自己指定的 ID 数组（1–128 项，ID 0–586），查看“板上已保存路线”。关闭前向避障，然后启动巡游。启动/恢复会自动在 OFF 或 CAT 模式下开启 BOTH（猫与标签），已有 TAGS/BOTH 设置保留，无需另按识别按钮。按当前目标顺序展示真实标签，居中且宽度达到 `tagStopWidth` 才算到达；日志为 `TAG_REACHED <ID>`，随后切换下一个，末尾循环回到首个。每次启动从数组首项开始。启动逐步等待 STOP、当前编号 GET_CONFIG 的 DATA/DONE、SESSION_START 确认；准备期间暂停自动遥测，每阶段超时最多重试两次。网页固定显示当前步骤和最后的故障/动作拒绝原因。没有保存过路线的新设备以空路线启动，要求用户先保存；已有保存路线继续使用。搜索仍受原有 360°/`searchTimeoutMs` 限制，轮子架空时编码器转角也会累计。

本轮 Uno 固件按用户要求将默认轮距改为 120 mm，复位后 `GET_CONFIG` 应回读 `TRACK_MM=120.0`；原默认 0 会使巡游因 `geometry not confirmed` 停止。网页仍可修改轮径/轮距，临时修改在复位后恢复默认，应与 ESP 策略参数一致。120 mm 是用户指定的默认值，不是此次实测。串口失联也会停止，不应通过关闭前向避障解释或绕过。关闭前向开关不证明巡游、标签识别或长期通信稳定性已验收。

PowerShell 运行 `./build.ps1` 编译；加 `-Upload -Port COM11` 烧录。构建目录使用 Windows 临时目录的英文路径，避免当前中文项目路径导致链接失败。`generate-config.mjs` 从原网页的概率和参数范围生成校验头；修改参数定义后再运行它。模型生成脚本由构建脚本自动执行并检查 SHA-256。

工具链：Arduino CLI、`esp32:esp32@3.3.12`、ArduinoJson 7.4.3。板型 `esp32:esp32:XIAO_ESP32S3:PSRAM=opi,PartitionScheme=max_app_8MB`。PSRAM 必须开启。
